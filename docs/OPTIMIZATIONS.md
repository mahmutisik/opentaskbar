## Widget flyouts (Audio mixer)

- **One surface, compositor hover.** The flyout's static content is one Direct2D surface; button hover and press layers are composition shapes whose opacity animates in the compositor, so moving the pointer never redraws. A slider drag redraws the one surface (no per-control windows or visual trees, unlike WPF's templates).
- **Layers rebuilt only when they change.** A redraw compares the buttons' rectangles and colors with the last set and keeps the composition layers when nothing moved (a slider drag or a volume key press recreates no visuals).
- **Fonts shared with the widget cards.** The flyout uses the dock's widget `Painter` (Inter, DirectWrite) instead of loading its own copy of the fonts; Inter Medium joins that one collection. Before this, every open flyout kept another 1.7 MB of font data for the life of the process.
- **Nothing kept while closed.** Closing releases the flyout's surfaces, layers, elements and the content with its Core Audio objects and app sessions (`ReleaseAppSessions`); private memory returns to where it was before the flyout opened.
- **No polling.** The mixer follows volume and default-device changes through Core Audio callbacks posted to its window; idle with the flyout open costs no CPU.
- **Calendar without a timer.** The calendar's live time redraws only when the clock card's text changes (the dock's widget tick already notices that and pokes the open flyout), so with seconds off it redraws once a minute. Day names come from ICU once per opening, not on every redraw.

## Settings window

- **WebView2 only while open.** The window's WebView (six `msedgewebview2` processes, about 177 MB private) is created when Settings opens and dropped when it closes; afterwards no WebView2 process is left and the dock process is back within 1 MB of where it was.
- **One window, one thread.** Settings runs on the dock's thread and message loop (no second UI thread or process of our own); page messages are queued and handled from the window procedure.
- **Debounced saves.** Slider drags apply and save 250 ms after the last move; the dock scale, which reserves the work area again, only when the mouse is released (OpenTaskbar's `_autoSaveTimer` and `CommitDockScale`).
- **Fonts from memory.** The page's Inter faces are served from the executable's embedded fonts through a custom protocol, not written to disk or inlined as base64.
- **No zip dependency.** Backups use a ~150-line zip writer/reader in `ot-ui/src/backup.rs` (stored entries out, stored and deflate in) instead of a zip crate: nothing new to download or audit, and the archives stay compatible with OpenTaskbar's.
- **Language list built on demand.** Native and English language names come from Windows' ICU when the Settings window opens; nothing is kept while it is closed.
- **Previews drawn on demand.** A widget's catalog preview is drawn only when its drawer opens (or a setting it shows changes), by the dock's own widget code into a software Direct2D target and encoded as PNG; OpenTaskbar keeps a live widget control per card. The running dock widget is reused when it exists.

## Theme packs

- **Tokens resolved once.** Selecting a theme reads its `widgets\pack.json` once and keeps the typed values for both color modes in two small maps; every palette lookup is a hash lookup. OpenTaskbar re-merges resource dictionaries and rebuilds its generated materials on each change. With no theme selected nothing is kept and the palettes are unchanged.
- **Built-in themes in the executable.** The six bundled themes (14 files, 16 KB) are embedded and copied only when a file is missing, as OpenTaskbar does with its manifest resources.
- **No new dependency.** `.ottheme` export and import reuse the zip writer and reader of the backups; the lenient JSON (comments, trailing commas) is a small pre-pass before `serde_json`.
- **Gallery redrawn on theme events only.** The Themes page is rebuilt when the theme list or selection changes (selection, new, import, delete, reload, size changes for the corner radius), not on other edits.
- **Editor defaults are a table, not live resources.** The theme editor's default values come from a table generated once from OpenTaskbar's XAML (85 tokens), so no resource dictionary exists at run time; only the Windows-derived colors are computed when the editor opens.
- **Picker without a second window.** The brush picker is a dialog inside the Settings page instead of another window (OpenTaskbar: a WPF window per opening); nothing is created when it is not open.

## Reliability fixes from the upstream comparison (2026-11-27)

- **No lost work during modal loops.** Posted work messages that arrive while the dock is borrowed are kept once and posted again when the borrow ends, instead of being dropped (a dropped frame used to stop the frame clock for good).
- **Taskbar watcher without polling.** The existing tracker hook reports Explorer's taskbar windows being shown or recreated; the session reacts only then. Hide retries settle on consecutive clean checks instead of the first success.
- **Explorer missing: bounded retries.** Degraded-mode retries back off (500 ms, 1 s, 2 s) and stop after about a minute instead of waking twice a second indefinitely; Explorer's TaskbarCreated or a new taskbar window wakes the session.

## Hardening from the upstream comparison (2026-11-27)

- **Theme files are size-capped before reading:** `theme.json` and `icons\pack.json` at 1 MiB, `widgets\pack.json` at 128 KiB (also in import validation).
- **Archive names:** theme and backup archives refuse names with NUL characters; a theme entry's joined path must stay inside the target folder.
- **Full backups:** the file size is checked before the archive is read into memory.
- **Settings load:** out-of-range numbers are brought into their range (a non-number takes the default) instead of replacing the whole file with defaults; the change and, when a file is still refused, the failing rule are logged. Saving stays strict. This differs from OpenTaskbar, which rejects the file.
- **Callbacks from outside:** a panic in the window-event hook or while parsing another process's tray message no longer aborts the dock (`catch_unwind`); the panic hook logs it.
- **Recovery journal:** the journal is written through a temporary file named per write, and replaced by delete-then-rename when a plain rename fails.
